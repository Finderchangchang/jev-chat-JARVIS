不只会写，先看懂。

大多数助手直接给你一段话。Jev 先判断这条消息到底是什么，再决定怎么回。

判断

Jev 判断模型不写字，只在固定选项里选：真实意图、危险等级（0–9）、对方要什么、该不该马上回、最佳动作等 7 项，都带概率和把握度，约 1 秒出结果。

候选

生成模型起草 3 条候选回复——稳妥接话、给出行动或承诺、简短表态各一条，默认经 OpenRouter 调用 DeepSeek。Jev 再给这 3 条排序，标出概率。

填入

点一下，回复进输入框。程序只填不发，从不自动发送，也不碰转账、红包、收款。最后那一下永远是你按的。

Jev 聊天助手 vs 其他方案

同样是「帮你回消息」，差别在读得到多少、判不判断、以及谁按发送。

一个 App，六件事做扎实

Built for everyday chats — 不是演示用的 demo。

一套内核，多平台

判断、候选、排序、填入都在同一个内核里。新增一个 App 只需要实现一个几十行的适配器，其余全部复用。

非侵入

不改任何 App 的安装包，不走它们的接口或账号，不读数据库。只用系统无障碍服务读「屏幕上正在显示的对话」。

知识库与关联上下文

本地维护笔记和联系人档案（关系、别名、备注）。笔记分两种：常驻的每次都带，其余按标签或标题匹配当前对话自动命中；开启历史后再带上这个人最近的聊天。回复口径与知识库一致，不编造知识库外的内容。联系人可跨 App 关联。

读不到就 OCR

控件树里没有正文时自动截屏，用 ML Kit 中文离线识别，不上传图片、不需要 Google 服务。任何 App 都能在悬浮窗菜单里手动「截屏识别一次」。

接口全可配

判断 / 回复 / 视觉三路接口的地址、密钥、模型分别可填。内置 OpenRouter、博查 Jev、TypeSafe 直连、Vercel、OpenCode Zen、DeepSeek 官方、通义兼容预设，各自一键连通测试。只填一把 OpenRouter 密钥就能用。

隐私在本机

密钥只存在 App 私有空间。聊天内容只在判断那一刻发给你自己配置的接口，作者不架设服务器、不经手，也不落盘、不进日志。历史记录默认关闭，开了也只存本机。

常见问题

会不会自动帮我发送？

不会。程序只把回复填进输入框，从不自动发送，也不碰转账、红包、收款。发不发、怎么改，都是你自己决定。

支持 iOS 吗？

暂不支持 iOS。桌面端已经有独立版本：Windows（v0.1.6）、macOS（v0.3.0），加上 Android（v1.4），各自独立仓库维护。

电脑端能用吗？

能用。Windows 版（v0.1.6）截自己的聊天窗口 + 本地离线 OCR；macOS 版（v0.3.0）看屏 + 本地小模型判断。网页版暂无规划。

要准备什么密钥？

最少一把 OpenRouter API Key 就能跑起来：填在「判断接口」，回复和视觉接口留空会自动继承。也可以三路分开配，内置 OpenRouter、博查 Jev、TypeSafe 直连、Vercel、OpenCode Zen、DeepSeek 官方、通义兼容预设，各自一键测连通。Vercel 用 AI Gateway 密钥，OpenCode Zen 用 Zen 密钥，都是 TypeSafe 兼容接口。

我的聊天内容会被上传吗？

只在判断那一刻，把屏幕上最近几条消息、你填的关系描述发给你自己配置的接口（开了知识库还会带上命中的笔记和联系人备注，开了历史还会带上这个人最近的聊天），之后不落盘、不进日志，作者不架设服务器、不经手。密钥只存在 App 私有空间。历史记录默认关闭，开了也只存在本机。OCR 走的是 ML Kit 中文离线识别，图片不上传。

群聊准吗？还有哪些已知限制？
  • Jev 主要用英文训练，中文场景的判断质量会波动；题目是按亲密关系里的冲突场景校准的，群聊、工作聊天这类场景准确度会下降。
  • 群聊目前按一对一的方式分析，多人交叉对话时判断会不准。
  • 判断给出的是概率，不是确定结论，仅供参考。
  • 部分国产 ROM 的后台冻结策略可能让悬浮气泡短暂消失，开自启动和省电无限制可缓解。
  • X / Twitter 只在中文界面下验证过。
